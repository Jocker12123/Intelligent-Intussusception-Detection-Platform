## 2. 契约映射（我们的模型怎么落进"检测 + 分类"）

本项目的模型是**联合的 OBB 检测+分类模型**（YOLO-OBB 双模型委员会），输出只有一个连续"证据分"和一个病灶框，
不是可以干净拆开的两个阶段。按契约允许的方式映射：

```
detection.detect(image)
    └─ 完整跑一遍委员会推理 → score（证据分）+ 最佳病灶框
    └─ 返回 ROI(image=原图, box=框|None, score=证据分)
         · 故意**不裁剪 ROI**：本项目模型对"取景"高度敏感（病灶占画面比例是关键变量），
           裁掉上下文会改变判定；契约明确允许"全图送分类"（ROI(image=原图)）
         · 把 score 放在 ROI 上，是为了让分类模块**复用**同一份推理结果 ——
           否则每个请求跑两遍模型，而本项目绝大多数阴性样本的 score 恰好为 0，正是最易重复推理的那类

classification.classify(roi)
    └─ 优先复用 roi.score（不再推理）；score 缺失时才自己跑一遍
    └─ 按阈值 + 安全网判成三分类之一
```

→ **一次请求只跑一遍模型**。

### 2.1 双模型溯源（`detection_model_*` / `classification_model_*`）

平台新增了 A/B 双模型溯源：`pipeline.py` 读取两个子模块的 `NAME` / `VERSION` 常量。本项目的填法是：

| 侧 | 模块 | `NAME` | `VERSION` |
|---|---|---|---|
| 检测 A | `detection/__init__.py` | `intussusception-obb-detector` | `1.0.0` |
| 分类 B | `classification/__init__.py` | `intussusception-obb-decider` | `1.0.0` |

> 本项目是**联合的 OBB 检测+分类模型**：检测侧负责跑委员会拿到证据分与病灶框；
> 分类侧负责阈值判定 + 概率标定 + 安全网。因此拆成这两个名字，而不是虚构两个独立网络。
> 名字里**不含**实验代号、随机种子、训练配方等内部信息（避免泄露训练细节）。

### 2.2 病灶框标注图（`ROI.annotated_image`）

平台新增「原图 / AI 标注图」切换与打印报告优先使用标注图。本实现：

* **阳性**：把病灶 OBB 四角点画成红色多边形 + 顶部状态条「AI 检出疑似病灶 证据分 x.xxx」；
* **阴性 / 图像质量不佳**：**不画框**（避免在阴性结果上画框造成误导），只加状态条「AI 未检出明确病灶 证据分 x.xxx」；
* 形态用 **JPEG 字节**（契约推荐，平台侧零依赖）；编码失败返回 `None`，**绝不影响诊断结果**；
* **始终提供**这张派生图：平台在 DICOM 输入下默认展示标注图，恒定提供可避免 DICOM 原图显示异常。

同时，`roi_box` **只在判定为阳性时给出**（检测阶段即按阈值门控）——否则阴性结果也会带一个病灶框。
实测标注图体积：768×576 → 85 KB（标注图会增加约 30 ms 的编码开销，端到端仍在 1.0–2.5 s）。

### 2.3 DICOM（`.dcm`）支持情况

算法侧**支持 DICOM**（`pipeline.load_image` 用 pydicom 解析像素，`model_core` 负责转 BGR）。
以下均为实测结果（构造各类变体走平台同一条入口），输入影像为一张已知阳性帧：

| DICOM 变体 | 结果 |
|---|---|
| 8 位 / 16 位 MONOCHROME2 | ✅ 阳性 0.9923 |
| 隐式 VR 小端 | ✅ |
| 带 RescaleSlope/Intercept | ✅（16 位 min-max 归一化会抵消线性 rescale） |
| **多帧 cine（`(frames,H,W)`）** | ✅ 均匀抽 ≤3 帧逐帧打分，**取最佳帧**（修前会被判「图像质量不佳」） |
| **RLE 无损压缩** | ✅ pydicom 原生解码 |
| **JPEG Baseline** | ✅ 经 Pillow 插件解码 |
| **JPEG2000 无损** | ✅ 经 Pillow 插件解码 |
| JPEG-LS | ⚠️ 未验证（需额外解码器，如 `pyjpegls` / `gdcm`） |
| **MONOCHROME1（反相）** | ⚠️ **未处理**：`pipeline.load_image` 只回传 `pixel_array`，丢失了 PhotometricInterpretation，算法侧无从得知需要反相。超声几乎都是 MONOCHROME2，风险低；若要覆盖，需平台在 `load_image` 里一并回传该标签，或按 MONOCHROME1 预反相。 |

**已知的平台侧问题（已修，请审阅）**：`routers/images.py` 原先**先按客户端声明的 `content_type` 拦截**，
而浏览器选中 `.dcm` 时 `File.type` 常为空串 → multipart 该部分没有 Content-Type → `file.content_type` 为 `None`
→ 返回 `400 Unsupported type: None`；声明成 `application/octet-stream` 同样被拒。
平台自己写了字节嗅探（`_sniff_image_type`）正是为了不信任客户端声明，却先被声明卡住。
已改为**以嗅探结果为准**：`声明类型或嗅探类型任一在允许清单内即放行`，并保留"普通图片声明与内容必须一致"的校验。
实测：无 Content-Type / `application/octet-stream` / `application/dicom` 三种情形均 200；
真 PNG 谎报 jpeg 仍 400、随机字节仍 400，安全性未削弱。

## 3. 策略与阈值

### 3.0 置信度（`confidence`）是**标定后的概率**，不是原始证据分

平台契约把 `confidence` 定义为「置信度 0~1」，前端在 `class_probabilities` 缺失时直接用它展示。
而模型内部输出的是一个**未标定的证据分**（跨模型几何平均，取值范围不受约束）——
若直接填进 `confidence`，一个"稳稳的阳性"会被显示成 `39.8%`，看着像没把握。因此这里做了一次**单调标定**：

| 判定 | `confidence` 的含义 |
|---|---|
| 肠套叠阳性 | `P(阳性 \| 证据分 ≥ s)` |
| 肠套叠阴性 | `P(阴性 \| 证据分 ≤ s)` |
| 图像质量不佳 | 固定 0.90（安全网） |

* 标定表在 **190 正 / 149 负 的留出集**上一次性拟合，估计量是**拉普拉斯平滑的阈值精度**（α=1）并做单调化，
  上下限 `[0.50, 0.999]`（不宣称 100%）；
* **决策阈值完全不受影响**——同一批 339 张复核，分类结果逐位不变
  （关安全网 183/9/7/140 → Prec 0.9531 / Acc 0.9528；开安全网 4 张转「图像质量不佳」）；
* 校验点：证据分 = 阈值 0.014451 处，标定值 0.9485 ≈ 同批实测 Precision 0.9531；
* `class_probabilities` 同步改为由标定值导出的三分类概率（此前填的是 `{score, 1-score, 0}`，不是概率）。

**全语料实测效果**（6,998 张）：`confidence < 50%` 的图片由 **350 张降为 0 张**，
其中 321 张原本是"判定正确、只是数字小"的假低置信。

### 3.1 默认策略 `v1`（现部署）

```
委员会 : intussusception-obb-v1-large.pt + intussusception-obb-v1-compact.pt       恰好 2 个模型
门控   : quorum=1，跨模型一致所需 OBB IoU ≥ 0.05
多尺度 : 640 首推；某模型 640 最高 conf < 0.20 才复推 1280
候选   : conf ≥ 0.001，每模型取 top-3
融合   : geo = sqrt(v_11s × v_11n)，两个成员都必须给出有效值，否则记 0
判定   : score ≥ 0.014451 → 肠套叠阳性；否则 肠套叠阴性
```

阈值来源：dev 负样本（450 张 `normal/`）的 94.3 分位。**该阈值可直接部署**——它对留出负样本的
标定偏差因子仅 **1.05**（本地实测）。

339 张 Final Test 实测：**TP=183 FP=9 FN=7 TN=140 → Precision 0.9531 / Accuracy 0.9528 /
Sensitivity 0.9632 / ROC-AUC 0.9772**；双 95% 可行 TARGET_FPR 带 [0.0550, 0.0600]。

### 3.2 实验策略 `v2`（**默认被硬性护栏挡住，勿用于临床**）

由 4 对同类模型取均值融合。它的**判别力更好**：
AUC 0.9946（vs 0.9772）、7 张原本完全静默的漏检 **7/7 救回**、可行带 0.0050 → **0.0230**。

但它的**阈值尚未在 out-of-fold 数据上重锁**：dev 负样本被用于训练（样本内），标定偏差因子达 **1.63**，
直接沿用同一常量会让 Precision 掉到 **0.9307（<95%）**。因此：

```python
# model_core.py
V2_THRESHOLD_CALIBRATED = False   # 未重锁前，启用 v2 会直接抛错
```

用无偏数据把阈值标定好之后，把该开关置 True 并更新 `POLICIES["v2"]["threshold"]` 即可切换（代码路径已就绪）。

### 3.3 安全网（`SAFETY_NET = True`）

```
score == 0 且 黑像素占比 > 0.70  →  返回「图像质量不佳」（建议提高增益/更换切面复扫）
                                 而不是「肠套叠阴性」
```

* **收益**：190 张阳性里 6 张整图完全无响应，其中 **4 张**（`图片 (18)(54)(58)(59)`）被该规则覆盖，
  不再被报成"阴性"；
* **代价**：独立 dev 负样本 450 张上误触发 10 张 = **2.2%** 的阴性会被要求复扫
  （test 上 0/149 属同分布下的幸运抽样，**以 2.2% 为准**）；
* **定位**：**启发式安全网，不是统计判定**。可开关、可随证据更新。

## 4. 已排除的方向（避免重复走）

| 方向 | 结论 |
|---|---|
| 提高推理分辨率（1536/2048） | 不改变病灶相对尺度，多次证伪 |
| 裁黑边 / 裁超声扇区 | 全测试集外接框保留率 p05=0.92，没有可裁的黑边 |
| 推理侧切片 / 中心裁剪 / 弱响应引导复判 | **两种不同设计同型失败**：阈值被负样本抬到 0.81，AUC 0.9772→0.9455 |
| 光度/增益归一化（CLAHE、百分位拉伸、Gamma） | 对 7 张漏检**分数仍是 0.000**，只有几何裁剪才点亮 |
| 亚型平衡负样本过采样、分辨率条件阈值 | dev 与 final 给出相反排序 / 标定方向错误 |
| 跨 run / 跨配方委员会 | 完整枚举后无优势；基线本就是 28 个两委员会里的第 2 名 |

根因结论：模型学到的是 **「紧裁剪 ⇒ 阳性」的捷径**（正样本全是紧贴病灶的裁剪、负样本全是宽帧）。
v2 的"对称取景随机化"正是针对这一点，因此才有效（6/7 静默漏检被救回）。

## 8. 影子模式标定（为切换 v2 铺路，**零 GPU、零延迟影响**）

v2 的判别力更好但阈值没有合法来源（见 §3.2）。**推荐的解法是影子标定**，而不是再跑 10h CV
（后者已做过本地预验证并否定）。

### 8.1 为什么不用"请求内实时影子"

`shadow.SHADOW_ENABLED=True` 虽然只入队不阻塞，但后台 v2 融合推理 = **8 个模型**，会和请求抢 CPU。
本地 A/B 实测（Ryzen 7 5700U，CPU 推理）：

| 配置 | 请求中位耗时 |
|---|---|
| 影子关闭 | 1057 ms |
| 影子开启（不限速） | 2217 ms（**拖慢 2.1×**） |
| 影子开启（限速 3/min） | 2296 ms（仍 +1156 ms） |

→ 限速只降频率、不降单次争用。**因此 `SHADOW_ENABLED` 默认 False。**

### 8.2 推荐方式：批量回填（对已存盘影像）

```powershell
cd backend
# 回填平台已上传的全部影像（默认取 config.UPLOAD_DIR）
D:\Program\miniconda3\envs\detect\python.exe -m algorithm.backfill_shadow
# 限量试跑 / 指定目录 / 已知整批为阴性时顺手打标
D:\Program\miniconda3\envs\detect\python.exe -m algorithm.backfill_shadow --images D:\normal --assume-label 0
# 看进度
D:\Program\miniconda3\envs\detect\python.exe -m algorithm.backfill_shadow --status
```

* 写入 `algorithm/shadow_data/shadow.jsonl`，按图像 md5 去重、**可中断续跑**（实测二次运行 0 新增 / 8 跳过）；
* 图像存一份到 `shadow_data/images/<md5>.jpg` 便于复核；关掉 `SHADOW_SAVE_IMAGES` 则不存；
* 建议用 Windows 计划任务 / cron **每晚跑一次**。实测约 **4.2 s/张**（8 模型）。

### 8.3 标定与判定

```powershell
D:\Program\miniconda3\envs\detect\python.exe -m algorithm.calibrate_shadow --export   # 出 labels.csv + review.html
#   ← 人工/临床填 label 列（1=阳性，0=阴性）
D:\Program\miniconda3\envs\detect\python.exe -m algorithm.calibrate_shadow --fit
```

判定逻辑（对应 p27 的教训）：

* **不取边界点** —— 取"Prec≥0.95 且 Acc≥0.95"的**可行阈值区间中点**，并要求区间宽度 ≥0.010；
* **给出同数据上部署策略的对照**（含 bootstrap 5% 下界），避免"换了数据才好"的错觉；
* 默认 **`--mode relative`（相对占优）**：点估计均 ≥0.95 **且**同批数据上（点估计与 5% 下界）都不劣于 v1
  且可行区间够宽 → 建议切换；
* `--mode strict`（绝对 5% 下界 ≥0.95）在小样本下**谁都过不了**——实测在 339 张上
  现部署策略的下界也只有 Prec 0.9293 / Acc 0.9323；要把 Acc 下界抬到 0.95 需 n≈3459。
  该模式仅在你确需绝对保证且样本足够时使用。
* 门槛：默认阳性 ≥120 且阴性 ≥120 才拟合（`MIN_POS/MIN_NEG`）。

判定通过后按提示改三处即可切换：`POLICIES["v2"]["threshold"]`、`V2_THRESHOLD_CALIBRATED=True`、
`POLICY="v2"`，然后重跑 `eval_algorithm.py` 复核。

> 影子样本是**真正无偏**的（模型从没见过它们），比交叉验证的折外分数更干净，且不需要任何 GPU。

## 9. 必须随结果一起理解的边界

1. **同配方只换随机种子，Accuracy 摆动 ±3.5pp**（4 个种子）。v1 是其中最好的一次；
   0.9528 是**点估计**，不代表该配方的稳定水平。
2. **v1 的双 95% 只对 73% 的负样本 bootstrap 重采样成立**（融合为 99%）→ 应表述为"点估计 + 区间"。
3. **6/190 的阳性在整图推理下完全无响应**（`enema_failure` 低增益小病灶）；其中 4 张由安全网兜住，
   另 2 张（`图片 (20)(124)`）仍无法覆盖。
